## Task 1 — Record the layering and dead-code policy

Create `docs/project/design/MAD_LAYERING_AND_DEAD_CODE.md`.

**Status:** decision record, agreed 2026-11-28.

**Content to capture:**

1. The three representations and their roles, with the history that produced them:
   * `Rptq*` — the canonical persistence model. It was autogenerated Core Data; it is
     now a hand-maintained contract over the portable SQLite store. It is what the
     application writes, saves, converts, and renders. Never add Core Data back.
   * `MADQuery*` — the SQL definition and compiler: the query graph, select
     expressions, predicates, and the dialect-specific SQL it emits.
   * `MADModel*` — the document-scoped read model the designer UI binds to. It is a
     store row identifier plus a weak context plus copied display values, resolved
     lazily.
2. The rule: **write through `Rptq`, read and observe through `MADModel`, compile SQL
   through `MADQuery`.** New code should state which layer it belongs to. Cross-layer
   copies are what produced the duplicate representations; do not add another.
3. Why the file count is not the problem: the 92 query-named files are mostly
   single-purpose builders; the accidental complexity was the Core Data tax (a fourth
   representation), not the three layers. Do not propose merging files; the
   `docs/developers/architecture/model-layer.md` §7 already explains why that touches
   the pbxproj, both CMake source lists, the Linux header shim, and every import for a
   cosmetic gain.
4. The dead-code rule: **finish it or delete it; never leave it compiled-nowhere.**
   * If an unfinished start encodes an intent the project still holds, write the
     intent in this record and add a test that will fail until it is wired; then the
     code may stay.
   * Otherwise delete it in a dedicated, behaviour-free commit.
   * The confirmed-dead inventory, each with a decision:
     - `MADQueryFullTableEnumerator` — decide explicitly: wire fast enumeration into
       the query-graph walk with a test, or delete. It is a tiny class and has no
       caller.
     - `MADDatabaseResultValue` — dead near-copy of the SQLite factories; delete one
       copy.
     - `MADReportFormatterCache` — in no target; wire or delete.
     - `MADArrayCachingEnumerator` — in no target; delete.
     - The vestigial `MADModel*` surface in `model-layer.md` §7B — fix or delete.
   * The rule applies to the entries already recorded in `BUGS.md`; link the relevant
     headings rather than repeating their text.
5. Non-goals: merging files, moving directories, changing behaviour in this pass.

**Acceptance:** a reader can classify a class into one of the three layers and knows

## Task 2 — Record the error and nullability convention

Create `docs/project/design/MAD_ERROR_AND_NULLABILITY.md`.

**Status:** decision record, agreed in principle 2026-11-28; adoption is phased, and
no code changes are part of this task.

**Content to capture:**

1. The three outcomes, and when each applies:
   * **Programmer error** — a nil where the declaration says nonnull, an invalid
     index, a mis-wired queue. Raise `NSInvalidArgumentException`, or use
     `NSParameterAssert`, at the public entry point.
   * **Recoverable runtime failure** — network, file, SQL, credentials. Return `nil`
     or `NO` and fill an `NSError **`. Never `@throw` the `NSError` object; it is not
     an `NSException` and the codebase's `@catch (NSException *)` cannot catch it.
   * **Expected absence** — a lookup that legitimately finds nothing. Return `nil`
     without an error.
2. Correct the framing: "the app never throws" is not the convention, and it was
   never Apple's. The convention is the three-way split above.
3. Scope: public framework headers first. Do not retrofit implementation files or
   private methods; a nil-tolerant internal path is not a contract violation.
4. Adoption order: `MADDatabase` and the three drivers (`MADMySQL`, `MADTdsClient`,
   `MADPostgres`) at the wire boundary; then `MADFoundation`; then `MADFileManager`;
   then the application targets.
5. The known violations to fix when the owning code is next touched, linking the
   entries rather than duplicating them:
   * `MADDataTable`'s caching pair throws the `NSError` object.
   * `MADElementStylizedText` accepts a nullable font name that crashes.
   * The fourteen `nullability.NullReturnedFromNonnull` /
     `NullPassedToNonnull` analyzer sites.
   * `MADQueryFull` treats its `error` out-parameter as an input and drops the sort
     error.
6. The immediate mechanical fixes (not this pass): make the caching pair throw an
   `NSException` or return `NO`; make the font-name annotation honest; NULL-check the
   `error` parameter and read `sortError`.

**Acceptance:** a new public method has a stated outcome and honest nullability
annotations; a reader knows not to sweep the implementation files.

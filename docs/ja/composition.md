# コンポジションレポート

**コンポジションレポート**は、他のレポートを1つの`.mad`ドキュメントに統合します。取り込む各レポートは**ソース**であり、ドキュメントの既定レポートは**結果**です。結果は、各ソースの結果テーブルを結合して、それ自体が新しいレポートになります。

コンポジションは、中間にフェデレーションサーバーを置かずに、1つのポータブルなドキュメントで複数のデータベース——MySQL、PostgreSQL、SQL Server、SQLite——にまたがる手段です。ソースは**レイアウトごと**ドキュメントに取り込まれます。結合しても、ソースがテーブルに平坦化されることはありません。コンポジションのすべてのメンバーは完全なレポートです。

> **プラットフォーム:** コンポジションレポートは **MAD Designer for macOS**（0.8）と **MAD Designer for Windows**（0.8）で利用できます。iOSアプリはまだコンポジションを作成できません。このページではデスクトップアプリケーションについて説明します。


## メンタルモデル

> コンポジションレポートは、他のレポートを1つに統合します。既存のレポート（**ソース**）を取り込み、その結果テーブルを結合して新しい**結果**レポートを構築し、表示する結果の**列**を選択し、その結果を通常のレポートとまったく同じように設計・表示します。ソースを選択すると、そのソースのクエリ、レイアウト、行が再び表示されます。

ワークフローは4つの動詞で説明できます：**ソースを追加 → 結合 → 列を選択 → 選択**。

| 用語 | 意味 |
|---|---|
| **コンポジションレポート** | レポートのグラフ——結果とそのソース——を保持する`.mad`ドキュメント。 |
| **結果** | ドキュメントの既定レポート。ソースのマテリアライズ済みテーブルを結合し、最初に開かれ、既定で印刷・エクスポートされるレポート。 |
| **ソース** | コンポジションに取り込まれた子レポート。独自のクエリ、データベース接続、レイアウト、行を保持します。 |
| **レポート列** | 結果が自身のレイアウトと親に公開するフィールド。クエリワークスペース（macOSでは**出力…**項目、Windowsでは**列**）で編集します。 |
| **レイアウトなしのソース** | レポートにまだ要素がないソース。デザイナはレイアウトの作成を提案し、ビューアはその行をテーブルとして表示します。 |

### すべてのメンバーがレポート

この機能を理解しやすくするのはこの規則です。ソースは取り込み時にテーブルへと縮小されません。クエリ定義、自身のレポートレイアウト、データがすべて一緒に取り込まれ、同じ`.mad`ドキュメントに保存されます。行は`.mad`の内部ではなく、コンパニオンストレージ（ドキュメントの隣にある`.maddb`ファイルと`.mdcache`ファイル）に残ります。

**ナビゲーション**ピッカー（macOS）または**コンポーネント**ピッカーとコンポジションペイン（Windows）でソースを選択すると、**3つのワークスペースすべて**——クエリ、デザイナ、ビューア——がそのソースに切り替わります。レイアウトなしのソースも有効なレポートです。ビューアはページではなく、キャッシュされた行をグリッドで表示します。



## コンポジションの作成

### macOS

* **File ▸ New Document…** は **Standard Report** と **コンポジションレポート**を提供します。コンポジションレポートを選ぶと、既存の`.mad`レポートを1つ以上選択し、次に新しいコンポジションの保存先を指定します。
* **File ▸ New Composition…** は同じフローの直接コマンドです。
* **File ▸ Convert to Composition…** は開いている標準レポートを、レイアウトを保ったまま1ソースのコンポジションに変換します。
* **MAD Query**ワークスペースでは、追加メニューからテーブル、新しいデータベース接続からの**ソースクエリ**、**読み込んだレポート**、または合成された**ルートクエリ**を追加できます。

ツールバーの**ナビゲーション**ピッカーは、最初に**結果**（*結果 — <name>*と表示）を一覧し、その後に各ソースを一覧します。項目を選択してもアクティブなワークスペースは変わりません。そのワークスペースが表示するレポートが変わるだけです。

### Windows

* **File ▸ New Composition…** は既存のレポートからコンポジションを作成します。
* **File ▸ Import…** はレポートを開いているコンポジションのソースとして追加します。
* **File ▸ Convert to Composition** は開いている標準レポートをコンポジションに変換します。

ドッキングされた**コンポジション**ペインがワークスペースの横にあります（標準レポートでは表示されません）。そのグラフは深さ0に結果を、その下にソースを表示し、コネクターは消費する側を指します。ペインとツールバーの**コンポーネント**ピッカーは1つの選択を共有し、ペインは折りたたむことができ、ピッカーは残ります。

## ソースの結合と列の選択

結果のキャンバスで、あるソースカードのフィールドを別のソースのフィールドへドラッグして結合を作成し、結合バッジをクリックしてその種類（`INNER`、`LEFT OUTER`、`RIGHT OUTER`、`FULL OUTER`、`CROSS`）を変更するか、方向を反転します。結果は通常のクエリです。任意の数のソースを結合し、フィルタ、グループ化、並べ替えを行えます。

それ自体がコンポジションであるソースは、自身のソースを伴ってグラフに加わります。親はそのコンポジションの結果を参照します。合成するノードは子だけを参照し、リモートテーブルを参照することはありません。そのため各リーフは自身のデータベースに対して実行され、すべての結合ステップはSQLite内でローカルに実行されます。

結果の**レポート列**エディタを使って、結果が公開するフィールドを選択、名前変更、順序付けします。結果のデザイナのフィールドリストはまさにその集合です。ソースは自身のクエリフィールドを公開します。

## 更新、認証情報、プライバシー

更新はグラフを**子から先に、結果を最後に**実行します。各リーフは自身の認証情報を使って自身のデータベースに対して実行されます。各合成レポートは子のマテリアライズ済みテーブル上でローカルに実行されます。各ノードは自身のテーブルをマテリアライズし、ノードが失敗すると更新は失敗しますが、以前の完全な結果は読めるまま残ります。

そのためマルチソースのコンポジションは、**ソースごとに1つの認証情報**を、1枚ずつシートで要求します。ドライバ、ホスト、ポート、データベース、および秘密でないユーザー名はあらかじめ入力されています。パスワードが`.mad`ファイルに保存されることはありません。macOSはキーチェーン（または現在のセッション）に、Windowsはセッションまたはプラットフォームの認証情報ストアに保持します。SQLiteのソースは認証情報を必要としません。

## サンプル

[`Samples/Reports`](https://github.com/mthomason/MAD/tree/master/Samples/Reports)には実行可能なコンポジションが2つあります：

* **`Chinook-Composition.mad`** — 2つのSQLiteソース（独自のレイアウトを持つAlbumsレポートと、レイアウトを持たないArtistsレポート）を結果に結合したもの。同梱の`chinook.sqlite3`以外に何も必要としません。
* **`Composition-MySQL-PostgreSQL-SQLServer.mad`** — MySQL、PostgreSQL、SQL Serverのそれぞれから小さなテーブルを1つずつ取り、`demo_id`で結合したもの。1つのドキュメントが3つのデータベースにまたがることを示します。

3つのライブサーバーを起動し、クロスデータベースのテーブルをシードするには、1つの冪等なスクリプトを使います（macOS、Linux、WindowsのGit Bash）：

```sh
./Samples/setup-databases.sh up
```

Windows PowerShellの場合：

```powershell
.\Samples\setup-databases.ps1 -Action up
```

`up`はテストデータベース用スクリプトを通じて固定されたコンテナを作成または起動し、`composition_demo`テーブルを各サーバーに読み込みます。`status`はコンテナと行数を報告し、`down`はそれらを停止します。同じSQLはDockerなしで`./Samples/setup-databases.sh sql`により出力できます。初回実行のウォークスルー（ソースごとのパスワードプロンプトを含む）については[サンプルガイド](https://github.com/mthomason/MAD/blob/master/Samples/README.md)を参照してください。

## 現在の制限

* **同一ドキュメントのみ。** 各ソースの定義とレイアウトは1つの`.mad`ファイルの内部にあります。別のファイルのレポートを参照することはできません。
* **合成レポートごとに最大10個の直接の子。** エンジンのSQLiteビルドは10個のアタッチされたデータベースを許可します。デザイナは11個目の子を拒否します。
* **ネストされたコンポジションはクエリワークスペースで読み取り専用です。** それ自体がコンポジションであるソースは、結合するソースを表示しますが、ネストされたコンポーザーを直接作成することは後の作業です。
* **`json-report`は結果のみをエクスポートします。** 他のすべてのエクスポート形式は選択されたレポートをエクスポートします。

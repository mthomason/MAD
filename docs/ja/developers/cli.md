# `mad` -- MAD Designerコマンドラインインターフェース

このページでは`mad`コマンドラインツールについて説明します。これはエンジンの組み込み面であり、アプリなしで`.mad`ドキュメントを試す最速の方法です。コンテナとストアに初めて触れる場合は、先にフォーマット仕様をお読みください。

このドキュメントは、ユーザーインターフェースなしで`.mad`ドキュメントを開き、検査し、更新し、エクスポートするコマンドラインツールを定義します。

この記録は、Apple アプリケーションのプレゼンテーション層がすべて UIKit だった時期に書かれたもので、そのためネイティブの macOS アプリケーションや Windows アプリケーションとして実行できませんでした。現在はネイティブの macOS（AppKit）アプリケーションと Windows（WPF）アプリケーションが存在します。`mad` CLI は、UI なしで同じエンジンを実行するヘッドレス経路として残っています。データパス——ドキュメントを開き、クエリを実行し、キャッシュを埋め、レポートをレンダリングする——はすでにほぼ完全に UIKit から自由であり（§4参照）、それが CLI を移植可能にしています。

---

## 1. スコープ

**スコープ内。** 単一のバイナリ`mad`で、次のことができるもの:

- `.mad`ドキュメントを開き、その内容を報告する
- ドキュメントが構築されたデータベーススキーマを出力する
- ドキュメントが定義するクエリをSQLとして出力する
- ソースデータベースに接続し、クエリを実行して行キャッシュを埋める
- レンダリングされたレポートをエクスポートする

**意図的にスコープ外。** ドキュメントを編集するものすべて。CLIはドキュメントを読み、実行しますが、設計はしません。引数解析、動詞、終了コードが表面のすべてです。

---

## 2. なぜ最初にCLIか

| | CLI | Macアプリ |
|---|---|---|
| UIツールキットが必要 | いいえ | AppKit（書き換え）またはCatalyst（却下） |
| フレームワークのポータビリティが必要 | **はい** | はい |
| 行キャッシュのポータビリティが必要 | **はい** | はい |
| `.mad`の定義が必要 | **はい** | はい |
| 求めていたものを提供する | はい | はい |
| フォーマットが変わったら捨てる作業 | なし | UI |

Macアプリケーションが存在するために必要なものすべて——ポータブルなフレームワーク、定義されたファイルフォーマット、複数プラットフォーム向けにビルドされたライブラリ——を、CLIは先に必要とします。UIポートを先に行うのは、同じ問題を発見するための高価な方法です。Macアプリケーションは別の決定として後で行われ、その時点でフレームワークはすでにポータブルです。

## 3. コマンド表面

```
mad <command> [options] <document.mad>
```


### `mad inspect <doc.mad>`

コンテナのみを読みます。データベース接続もCore Dataもありません。

```
$ mad inspect London.mad
London.mad
  format      v0 (bzip2 tar, no magic header)
  generator   MAD Designer
  version     1
  store       StoreContent/analyitics (SQLite 3.43.2, 126 pages)
  wal         present, 313152 bytes (not checkpointed)
  thumbnail   none
  elements    14 sections, 63 elements
```


これは`MAD_FORMAT.md` §7が実装されたことを証明する動詞です。v0サンプルで動作しなければなりません。また、フォーマットの危険を可視化する動詞でもあります——H2（チェックポイントされていないWAL）は黙って受け入れられるのではなく、報告されます。

### `mad schema <doc.mad>`

ドキュメント定義に取り込まれたデータベーススキーマを出力します。ドライバ、名前順に並べたテーブル、そして各テーブルのフィールドを表示型と`pk`マーカー付きで示します。作成時に保存されたスナップショットを読むため、認証情報もソースデータベースも必要ありません。（ここでの当初の計画はSQLの`CREATE TABLE`を出力することでしたが、スナップショットは各ソース方言の型名ではなく`MADDataType`抽象を保存するため、忠実な`CREATE TABLE`にはまだ存在しない方言ごとのマッピングが必要です。それまでの間、ツールが生成するのはこの読みやすい一覧です。）

### `mad query <doc.mad>`

ドキュメントのクエリが生成するSQLを、実行せずに出力します。これはアプリケーションの中心となる機能です——ユーザーがテーブル、結合、フィルタを組み立て、ソフトウェアがSQLを書く——ので、それを公開することが自然な最初の非自明な動詞です。

```
$ mad query London.mad --format sql
SELECT ... FROM ... WHERE ...
```


### `mad refresh <doc.mad>`

ソースデータベースに接続し、クエリを実行して行キャッシュを埋めます。これがデータパスであり、残りのすべてが依存する動詞です。

```
$ mad refresh London.mad --credentials user:pass
refreshed 148,392 rows in 1.21 s (122,638 rows/s)
cache  ~/Library/Caches/MADDesigner/<id>/<tag>.maddb
```


オプション: `--credentials`、`--host`、`--port`、`--database`、`--no-cache`（永続化せずに実行）、`--rows N`（N行で停止、スモークテスト用）。

`--rows`が存在するのは、ライブサーバーに対してCIで何百万行も取得せずにこの動詞をテスト可能にするためであり、`MADDataTableFastBenchmarkTests`のベンチマークがすでにこのパスが大規模でも測定可能であることを証明しているからです。

### `mad export <doc.mad>`

レポートをレンダリングして書き出します。

```
$ mad export London.mad --format pdf  --out London.pdf
$ mad export London.mad --format json --out -          # to the standard output
```


フォーマットはエクスポートシーム（§5.3）です。それぞれが`MADReportExporterRegistry`に登録されたクラスであり、使用法のテキストはビルドが持つものを列挙します。

| フォーマット | 書き出すもの | 実行場所 |
|---|---|---|
| `pdf` | レンダリングされたレポート（ページ、描画済み） | Apple: UIKitの`UIPrintPageRenderer`、Core Graphics。Linuxはできない理由を返す |
| `html` | レンダリングされたレポートを1つのHTMLファイルとして。ページごとに1つのページボックス、ブラウザから印刷 | 両プラットフォーム |
| `html-flow` | レンダリングされたレポートをリフロー可能なHTMLとして。セクションごとに1つのテーブル | 両プラットフォーム |
| `text` | 行を固定幅テーブルとして | 両プラットフォーム |
| `csv` | 行をRFC 4180 CSVとして | 両プラットフォーム |
| `json` | スキーマと行をJSONとして（§8.3） | 両プラットフォーム |
| `json-report` | `json`にレンダリングされたレポートのセクションを加えたもの | 両プラットフォーム |

`--out`はFoundation系フォーマットでは任意です——省略するか`-`を指定すると標準出力に書き出します——が、`pdf`では必須です。Foundation系フォーマットは、同じドキュメントに対してAppleとLinuxで同じバイトを書き出します（`Linux/README.md`。両プラットフォームによるLondonフィクスチャのエクスポートはダイジェストで一致します）。

**定義された順序。** エクスポートのグループ順はこの契約の一部であるため、プラットフォームの順序ではなく定義された順序です。テキストキーは大文字小文字を区別せずに比較し、次にUTF-8バイト上のコードポイント順で比較します。ケースフォールドはUnicode 17.0.0の単純な（1対1の）ケースフォールドで、チェックインされたテーブル（`MADFoundation/Source/NSString+Comparison.m`の`MADStringOrderingTable`、UCDの`CaseFolding.txt`のstatus-C/Sエントリから生成）として保持されています——ASCIIと、テーブルがマップするすべてのUnicodeペアはフォールドし、それ以外（発音記号を含む）はそれ自身のコードポイントとして比較されます。フォールドはすべての文字を小文字範囲に送り、それはすべてのASCII句読点バイトより後に来るため、句読点で始まるキー（`[1997] Black Light Syndrome`）は単語で始まるキー（`Core`）より前にソートされます——SQLiteの`NOCASE`が置くのと同じ位置です。UTF-8はコードポイント順を保つため、バイト比較はコードポイント比較です。1つのコンパレータ（`-[NSString mad_orderedCompare:]`とそのCコア`MADStringOrderedCompareUTF8`）が3つのサイトすべてを駆動します。キャッシュの`LSASC`照合順序、メモリ内のソート記述子（`MADDataTypeSelectorForSorting`）、およびレポートフォーマッタのグループ境界比較です。順序はプラットフォーム、OSリリース、ロケールをまたいで決定論的です。2026-10-25にローカライズされた順序から変更されたため、それ以前のエクスポートはそれ以後のエクスポートと等しく比較されません。

**`json-report`**（`MAD_LINUX.md` §10.1、§9 Phase E）は同じスキーマに、レンダリングされたレポートを`report`メンバーとして加えたものです。ページ、各ページの描画順のセクション（型、グループレベル、可視性）、各セクションの行、各ラインの要素種別、フレーム、解決済みテキストを含みます。テストとレンダラーが読むものであり、レンダラー自身の構造——何も描画しないページウォーク——であるため、PDFが示すものからドリフトできません。フレームはラインが**ページ上**のどこに位置するか（要素のフレームをそのセクションでオフセットしたもの）であり、レンダラーやブラウザが必要とするものです。レンダー半分は現在Linuxでコンパイルされるため、このフォーマットは両プラットフォームで動作します。

**`html`**はブラウザが印刷するページ形状の成果物です。ウォークされたページごとに1つのCSSページボックスを持ち、各要素はそのフレームに絶対配置され、解決済みテキストは要素自身のフォント、サイズ、ウェイト、傾き、装飾、配置で描かれます。改行ルールはレンダラーのものです（`NSLineBreakByTruncatingTail` -> `white-space: pre; overflow: hidden; text-overflow: ellipsis`）。埋め込みスタイルブロックを持ち、スクリプトを持たない1つのUTF-8ファイルです。**`html-flow`**は同じレポートからページを落としたものです。レポートセクションごとに`<section>`、セクションごとに`<table>`、要素ごとに`<td>`、ページ家具は一度だけ出力し、異なる要素スタイルごとに生成されたクラスを持ちます。これは読むためのビューであり、`json`がデータ契約です。どちらも色（ストアの色カラムは現在どちらのプラットフォームでも読み手がいません）や、Linuxでの画像（Appleのパスは`UIImage`から描画しますが、Linuxのエクスポートは空のボックスを置きます）を持ちません。

PDFへのレンダリングは`MADPrintPageRenderer`を通ります。共有シートのラッパー`MADActivityItemProviderPdf`がそのもう1つの呼び出し元であり、`MADActivityItemProviderDelegate.h`がそれが話すプロトコルです。3つともアプリではなく`MAD`フレームワークにあります。PDFが**ヘッドレス**でないことが重要です。それはUIKitの`UIPrintPageRenderer`であり、それゆえCLI側でまだ実装されている唯一のフォーマットです（§5.3参照）。

### `mad write <doc.mad> --out <copy.mad>`

ドキュメントを`.mad`として書き出します——*コピー*です。ドキュメントが読み込まれたgutsディレクトリを、v1ヘッダーで再びアーカイブします。読み込んだドキュメントを編集するものではなく、CLIは依然としてドキュメントを設計しません（§1）。この動詞の目的はバイト同一性の要件——2つのプラットフォームで書かれた同じドキュメントは同じファイルでなければならない——と、スクリプトが実行できるライターを必要とする§6.1のラウンドトリップフィクスチャです。

```
$ mad write London.portable.mad --out copy.mad --reproducible
wrote /tmp/copy.mad (16261 bytes, reproducible)
```


`--reproducible`は、時計とファイルシステムがアーカイブに刻むであろうものを固定します。固定の変更時刻（2001-01-12T00:00:00Z、PDFエクスポートが日付を固定する瞬間）、所有者とグループ0、ソートされたメンバーウォーク（`MADArchiveManager.reproducible`）です。これがないと、メンバーの実際のメタデータを持つ通常の保存が書き出されます。ドキュメントは両プラットフォームでヘッドレスに開かれる（`MADHeadlessDocument`）ため、比較の両側が同じライターを実行し、同じドキュメントがそこで同じバイトを書き出します（Londonフィクスチャで16,261バイト、`Linux/README.md`）。

### グローバルオプション

| オプション | 意味 |
|---|---|
| `--verbose` | データパスを各段階でログ出力する |
| `--quiet` | 結果以外のすべてを抑制する |
| `--credentials user:pass` | ソースデータベースの認証情報。指定がなければキーチェーン |
| `--host <name>` | ソースデータベースのホスト上書き（refresh、export） |
| `--port <n>` | ソースデータベースのポート上書き、1-65535（refresh、export） |
| `--database <name>` | ソースデータベース名の上書き（refresh、export） |
| `--no-keychain` | キーチェーンに一切触れない |
| `--format <name>` | 出力フォーマット |
| `--out <path>` | 出力パス。デフォルトは標準出力 |
| `--deterministic` | エクスポートの日付と識別子を固定し、変更のないデータに対する2回の実行をバイト同一にする |
| `--reproducible` | `.mad`アーカイブの入力——時刻、所有権、メンバー順——を固定する（`write`） |

接続定義——ホスト、ポート、データベース名——はドキュメントのポータブルストアの一部であり、ユーザー名とパスワードは決してそうではありません。`--host`、`--port`、`--database`はこの実行に限り保存された接続を上書きするため、チェックインされた1つのドキュメントを書き換えることなくCIサービスコンテナに対して実行できます。指定されないものは保存値を保ちます。Sqlite3ドキュメント（接続がファイルである）や、接続しない動詞（`inspect`、`schema`、`query`、`write`）では単に未使用です。認証情報は`--credentials`のままであり、ストアはユーザー名もパスワードも保持しません。

### 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 使用法エラー |
| 2 | ドキュメントを読めなかった、または`.mad`ではない |
| 3 | ソースデータベースに到達できない、または認証情報が拒否された |
| 4 | サーバー上でクエリが失敗した |
| 5 | エクスポートが失敗した |

個別のコードが重要なのは、このツールの最初の実際の用途がスクリプトであり、スクリプトは「ドキュメントが悪い」と「サーバーがダウンしている」を区別する必要があるからです。

## 4. CLIをビルドする前に存在しなければならないもの

データパスはすでにほぼUIKitフリーです。これは推定ではなく測定です。

| フレームワーク | UIKitをインポートするファイル | CLIが必要とするか |
|---|---|---|
| `MADDataStructures` | 0 / 37 | はい |
| `MADFileManager` | 0 / 31 | はい |
| `MADSqlite3` | 0 / 65 | はい |
| `MADMySQL` | 0 / 42 | はい |
| `MADTds` / `MADTdsClient` | 0 / 3, 0 / 9 | はい |
| `Scrimpter` | 0 / 48 | いいえ |
| `MADFoundation` | 4 / 66 | はい |
| `MADAPI` | 3 / 34 | 一部 |
| `MAD` | 28 / 464 | 一部 |

`MADFoundation`の4つのファイルが、ベースフレームワークのUIKit依存の全体を担っています。

| ファイル | UIKitの使用 | 処置 |
|---|---|---|
| `MADApplication.{h,m}` | `UIApplication`ラッパー | CLIには不要。ヘッドレスターゲットから除外 |
| `MADURLFactory.m:32` | `UIScreen.mainScreen.scale > 1.0` | 1回の呼び出し。iOS以外では2.0を返す |
| `MADOperation.m:550-563` | `beginBackgroundTaskWithName:` | 1つの機能。`#if TARGET_OS_IPHONE`でガード |

著者はすでに最後のもの（`MADOperation.m:21`）に印を付けています。*「ここでUIApplicationをインポートしなくて済めばいいのだが、実際これが最もクリーンな方法だ。」* ヘッドレスビルドにとってそれは最もクリーンな方法ではなく、ベースフレームワーク内でそれが当てはまる唯一の場所です。

`MADAPI`の3つのUIKitファイルは接続*ビューコントローラ*であり、単にヘッドレスのターゲットの一部ではありません。

### 4.1 リフレッシュコアを移動しなければならない

唯一の実質的な作業はこれです。リフレッシュのオーケストレーションは**アプリケーションターゲットにあり、フレームワークにはありません**。

| ファイル | 行数 | UIKitシンボル | 役割 |
|---|---|---|---|
| `MADDesigner/Source/MADOperationRefresh.m` | 131 | **0** | SQLを構築し、実行し、キャッシュを書き込む |
| `MADDesigner/Source/MADOperationRefreshReload.m` | 196 | 3 | UI側のリロード |
| `MADDesigner/Source/MADRefreshOperationReload.m` | 132 | 1 | UI側のリロード |

`MADOperationRefresh.m`は`MADAPI`、`MADFoundation`、`MAD`のみをインポートし、UIKitには触れません。それはすでにCLIのrefresh動詞であり、単に間違ったターゲットにあります。`MAD`フレームワークに移動し、2つの`Reload`オペレーションはアプリに残ります。それは彼らの名前がずっと言ってきたとおりです。

### 4.2 ヘッドレスターゲット

UIKitなしでコンパイルされる`MADFoundation`、`MADAPI`、`MAD`のビルド構成、およびCLIターゲット自体です。機械的には、`SUPPORTED_PLATFORMS`を`macosx`で拡張し、`LIBRARIES.md` §6のSDKごとのライブラリ検索パスを適用し、上記の3つのファイルレベルの除外を行います。

**Linuxで完了、2026-10-16**（`MAD_LINUX.md` §9 Phase D）。そしてこの方法で行われました。ヘッドレスターゲットは`Linux/CMakeLists.txt`がGNUstepに対してコンパイルする12のフレームワークであり、CLIはそれらの隣のターゲットです。§4.1が`MAD`フレームワークに割り当てた部分——リフレッシュチェーン——はそこへ移動し、予期していなかった部分——`UIDocument`である`MADocument`、その上に`MADCLIDocument`が構築された——は`MADDocumentDataProtocol`の背後にある`MADHeadlessDocument`で解決されます。同じデータ半分であり、ドキュメントライフサイクルもレンダリングするものもありません。`inspect`、`schema`、`query`、`refresh`は両プラットフォームで同じソースです。`export`はPDFでありApple側に残ります（§5.2、§9の段階分け）。macOSターゲットは依然としてTrack 5.1のものですが、今ではそれが欠いていたシームとドキュメントクラスを持っています。

## 5. 設計

### 5.1 1つのバイナリ、邪魔なフレームワークなし

`mad`はヘッドレスフレームワークを直接リンクします。アプリケーションバンドルを読み込まず、ビルドフェーズでCore Dataモデルが存在することを要求してはなりません。テストスイートがすでに遭遇した制約です（プロジェクトメモリの`MADTestReportFormatter`に関する注記参照）。

### 5.2 refresh動詞は測定済みのパスを再利用する

`mad refresh`はアプリケーションが呼ぶのと同じコードを呼ばなければなりません。`MADOperationRefresh` → `MADDatabase executeSQL:fieldKeys:onConnection:intoResultTable:` → `<MADDataTableWriting>`です。それを再実装してはなりません。`MADDataTableFastBenchmarkTests`で追加されたベンチマークは、まさにこのパスを200,000行で測定しており（取り込み1.16秒、一時領域2.5 MB）、それを退行させるCLIはユーザーの苦情ではなく失敗したテストとして現れます。

### 5.3 エクスポートはスイッチではなくプロトコル

`MAD_FORMAT.md`はドキュメントを記述し、ドキュメントはレポート要素を含みます。エクスポートは拡張ポイントであるべきで、開発者が「新しいドキュメントエクスポートフォーマット（例: PDFおよびJSONへのエクスポート）を作成する」というプロジェクトの明示的な目標に合致します。`<MADReportExporting>`を1つのメソッドで定義し、実装を登録します。そうすれば`--format json`はスイッチ内の新しい分岐ではなく、新しいクラスになります。

**2026-10-16に完了**。§5.1のドライバレジストリがすでに持つ形で行われました。`MADReportExporting.h`がプロトコル（フォーマットの名前、拡張子、`--out`が必要か、このビルドが生成できるか、および1つのエクスポートメソッド）、`MADReportExporterRegistry`がルックアップであり、各エクスポーターは`+load`で自身を登録します。したがって、プロセスが持つフォーマットはリンクしたものであり、CLIは名前で1つを要求します。`text`、`csv`、`json`はフレームワーク自身のもの（`MADReportExporterText/CSV/JSON`、純粋なFoundation、両プラットフォーム）です。`MADReportExportSource`はドキュメントを列と行として読む唯一の場所であり、フォーマットがドキュメントとは何かについて意見を異にすることはできません。`MADReportExportWriter`はバイトがファイルまたは標準出力に到達する唯一の場所です。

`json-report`、`html`、`html-flow`もシーム上にあり、レンダー半分のプロトコル（`MADDocumentRenderProtocol`。行を準備し、フォーマットし、フォーマッタを引き渡せるドキュメント）と1つのページウォーク（`MADReportPageBuilder`）の上に構築されています。**`pdf`も同様にシーム上にあります**。`MADReportExporterPDF`はどこでも登録され、その本体はCore Graphics（Appleのもの）であり、Apple以外では理由とともに`+isAvailable NO`と答えます（`MAD_LINUX.md` §10.2。Linuxライターが次のステップです）。CLIにはローカルの腕が残っていません。`pdf`を含むすべてのフォーマットはレジストリでルックアップされます。

### 5.4 認証情報

CLIは決してプロンプトを出してはなりません。`--credentials`を受け取るか、アプリケーションが書き込んだキーチェーンを読むか、終了コード3で失敗します。`--no-keychain`は、テスト実行が開発者の実際の認証情報を読み書きできないようにするために存在します。

### 5.5 実行する: Linuxイメージ

`Linux/build.sh --runtime`は`mad-cli:latest`をビルドします。CLIをPATHに置き、それがリンクする共有ライブラリとSqlite3サンプルデータベースを含むランタイム専用レイヤーです——コンパイラ、ソース、テストバイナリはありません（ディスク上283 MB。内容は`Linux/README.md`）。ドキュメントは保存されず、マウントされます。

	docker run --rm -v "$PWD/CLI/Fixtures":/docs:ro mad-cli:latest \
		mad inspect /docs/London.portable.mad
	docker run --rm -v "$PWD/CLI/Fixtures":/docs:ro mad-cli:latest \
		mad refresh /docs/MySQL.employees.mad --credentials root:root --rows 50

イメージは（2026-10-26、以前の未公開決定を覆して）`ghcr.io/mthomason/mad`として公開され、`latest`とコミットの短いSHAでタグ付けされ、masterへのプッシュごとに（および`workflow_dispatch`で）`.github/workflows/publish-image.yml`によってプッシュされます。公開タグは**linux/amd64**で、CIがubuntu-latest上でビルドします。Macのローカル`mad-cli:latest`はarm64であり、Appleシリコンでは公開タグに`--platform linux/amd64`が必要です（エミュレーション下で実行。フラグなしではプルが`no matching manifest`で失敗します）。公開イメージに対する同じ動詞:

	docker run --rm --platform linux/amd64 -v "$PWD/CLI/Fixtures":/docs:ro \
		ghcr.io/mthomason/mad mad inspect /docs/London.portable.mad

Sqlite3ドキュメントは、保存されたデータベース名をユーザーごとのApplication Supportディレクトリで解決します。イメージでは`/root/GNUstep/Library/ApplicationSupport`であり、`chinook.sqlite3`がそこにあるため、LondonとMusicのフィクスチャはセットアップなしでリフレッシュできます。行キャッシュは同じホームの下にあり、コンテナごとです。すべてのエクスポートがドキュメント自体をリフレッシュするため、キャッシュが実行間で永続化する必要はありません。公開イメージ内のLGPLコンポーネントは再リンクの申し出を義務付けます。`ThirdParty/Licenses/README.md`の書面による申し出がイメージを名指しします（`THIRD_PARTY_LICENSES.md` §9がレジスタエントリです）。

`Linux/build.sh --verify`はイメージを再ビルドし、反復可能なチェックを実行します。フィクスチャに対する6つの動詞すべて、各フォーマットの固定ダイジェスト、`pdf`の拒否、ライターのバイト、終了コードです（`Linux/verify-cli.sh`。`--live`は3つのライブデータベースを追加します）。

## 6. テスト

フォーマットとCLIは散文ではなく**ラウンドトリップフィクスチャ**で固定されます。

1. **コンテナの忠実性。** `Music.mad`と`London.mad`を展開し、再パックし、メンバーリストと各メンバーのバイトが変わっていないことをアサートします。これは`MAD_FORMAT.md` §2を固定し、H4（隠しファイル）を即座に捕捉します。**2026-10-16に着地**。`Linux/Tests/MADArchiveManagerTests.m`のラウンドトリップとして——`mad write`が両プラットフォームでコンテナを書くようになり——再現可能モードのバイトはMacのものに対して固定されています。
2. **v0可読性。** 両方の出荷サンプルに対する`mad inspect`が成功し、`MAD_FORMAT.md` §2の値を報告しなければなりません。チェックポイントされていないWALを含み、これはWALの危険が無視されるのではなく報告されていることを証明するアサーションです。
3. **キャッシュなしのラウンドトリップ。** ドキュメントを開き、リフレッシュし、エクスポートし、閉じ、再度開きます。2回目のオープンはネットワークを必要としてはなりません。これはフォーマットドキュメントの§5——キャッシュは派生かつ外部である——を固定します。
4. **スケール。** ローカルSQLiteソースに対して`mad refresh --rows 200000`を実行し、ベンチマークが使うのと同じ上限に対してアサートします。CLIが静かに遅いパスになってはなりません。
5. **終了コード。** §3の表の各行に1つのテスト、意図的に壊れた入力で駆動します。

フィクスチャはテストするサンプルの隣にあります。ライブのMySQL、SQL Server、PostgreSQLサーバーを必要とするテストは、到達できない場合に**スキップ**します。`MADMySQLLiveTests.m`、`MADTdsClientLiveTests.m`、`MADPostgresLiveTests.m`の既存の慣習に従います。

## 8. 未解決の問い

1. **CLIは出荷されるのか、それとも開発者ツールなのか。** これはコード署名、公証、インストーラが必要かどうか、そして`--credentials`が平文引数を受け入れてよいのかファイル記述子を取らなければならないのかを決めます。
2. **`mad`は外部ファイルから行キャッシュを受け入れるべきか。** パックされた`.mad`（フォーマットドキュメントの§8.3）はオフラインエクスポートを可能にします。まだ必要とするものはありません。
3. **JSONエクスポートの形状は何か。— 2026-10-16に回答: 両方、レポート半分は独自のフォーマットとして。** `--format json`はデータ契約であり、`--format json-report`はレンダリングされたレポートを追加メンバーとして加えます。形状は`MADReportExporterJSON.h`にあり、`MADReportExporterJSON`（データ半分、両プラットフォーム）と`MADReportExporterJSONReport`（レポートメンバー、レンダー半分がある場所）で実装されています。その列はクエリ自身のもので、SELECTリストが定義する順序——列エイリアス、ソート済み（`BUGS.md`、SELECTリストのエントリ）——であり、値はJSON型を保ちます。数値は数値、NULLは`null`、日付はISO 8601、バイナリはbase64です。

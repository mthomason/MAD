## 8. 开放问题

1. **存储到底需要是 Core Data 吗？** 它保存的定义是一个不大的对象图。在同一 SQLite 文件中使用手写架构可以消除 H3，消除格式中最后的 Apple 依赖，而且无论 CLI 做什么，它都是 Windows 的前提。这是 Core Data 迁移的设计决策，不是本文档的决策。
2. **缩略图应该放在文档里吗？** 它可以重新生成，就像行缓存一样，而且它是 `AdditionalContent/` 存在的唯一原因。移除它会让 `.mad` 的每个成员都成为权威数据。
3. **`.mad` 应该可选地携带行缓存吗？** 一种“打包”变体可以让文档在第二台设备上离线打开，代价是体积。目前没有这样做；提出这一点是因为这个名字会让人产生这种预期（§5）。
4. **内容变化应该使渲染缓存失效吗？** 现在已从*机制上*回答：`.madac` 缓存以文件名和页面大小为键，没有内容哈希，因此以相同文件名编辑文档会一直提供过期页面，直到文件被删除（§5.3）。开放的部分是产品决策——编辑*是否应该*使其失效——而用户本人的说法是，缓存是承重的，不是当前亟待处理的事情（§5.1）。因此这里只记录，现在不修复。

# TODO — 产品路线图与愿望清单

作者的产品愿望清单与战略路线图。活跃的工程任务记录在 [`TASKS.md`](TASKS.md)，未解决的缺陷固定在 [`BUGS.md`](BUGS.md)，架构设计位于 [`MAD_DATA_OBJECT.md`](MAD_DATA_OBJECT.md) 和 [`MAD_FUTURE.md`](MAD_FUTURE.md)。此处的条目在被要求时才会着手处理。

## 1. 数据对象与可组合表（`.mad` 作为表）

数据库公开基表（`employee`、`sales_data`）；`.mad` 报表将多个表连接、筛选并塑形为一张物化的 SQLite 结果表（`.maddb` + `.mdcache`）。下一个架构飞跃是让该输出成为一等、可寻址的表：

* **报表作为虚拟/物化数据库表**——为每个查询定义赋予稳定的标识与架构契约（`MADDataObjectSchema` / `MADDataObjectExecuting`，参见 [`MAD_DATA_OBJECT.md`](MAD_DATA_OBJECT.md)），使 `.mad` 报表的输出可以像数据库中的基表一样被查询（`SELECT` / `JOIN`）。
* **单个报表中的多个数据源**——允许一个 `.mad` 文档定义针对多个数据库的查询（例如 PostgreSQL + SQL Server + MySQL），将每个查询物化为本地 SQLite 表（`MADDataTableFast`），并在查询设计器中将它们连接起来，无需外部联邦服务器。
* **可组合子报表与语义 DAG**——在其他 `.mad` 报表内部链接 `.mad` 报表作为上游表源，形成一个可移植、按依赖排序的派生表 DAG（`mad run`）。
* **具名、可共享的数据快照**——将 `.maddb` + `.mdcache` 打包为可寻址、带版本的快照产物，无需数据库凭据即可离线传输，并能回答时间点审计问题。

## 2. 旧版报表迁移与互操作性

* **Crystal Reports（`.rpt`）转换器/导入器**——解析旧版 Crystal Reports `.rpt` 文件，将其数据库架构、表链接、公式/谓词以及分带区段布局（报表/页/分组页眉与页脚、明细）转换为开放的 `.mad` 文档。
* **更多旧版报表导入器**——支持将其他根深蒂固的企业报表定义（例如 SSRS `.rdl` / JasperReports `.jrxml`）导入 `.mad`。
* **仅架构的描述路径**——直接从查询图和已存储的架构快照推导报表输出的 `MADDataColumn` 架构，无需对活动数据库执行查询（同时填补零行 SQLite 架构的空白）。

## 3. 超越纸张范式：原生 UI 与呈现视图

在纸上打印（分页带区）应当只是查看 `.mad` 文档的一种范式。由于布局是参数化的，且行缓存位于设备本地的 SQLite 中，同一定义应当能够支撑丰富的原生 UI：

* **用于非打印探索的原生 UIKit 数据视图**——在设备上查看时，将报表的布局和底层 `.maddb` 数据渲染为可交互的原生 UIKit 集合/表组件，而不是仅呈现为固定尺寸的纸张页面。
* **交互式原始数据与示例表浏览器**——通过对 `.maddb` 的分页/虚拟化查询，完善示例表/原始数据显示，以便交互式地浏览、排序和检查不限数量的行。
* **图表元素**——绑定到查询分组和聚合的一等图表文档元素。
* **仪表板与 KPI 文档类型**——数据模型已经带有报表类型；在分页报表之外，增加多磁贴仪表板视图和可复用的 KPI 查询卡片。
* **公式元素（`Scrimpter` / 表达式引擎）**——将计算型公式元素引入设计器和渲染器（引擎选择记录在 [`MAD_SCRIPTING.md`](MAD_SCRIPTING.md) §8）。

## 4. AI 辅助创作（图优先、确定性）

* **自然语言到查询图与布局**——让 LLM 基于文档小于 100 KB 的架构快照，提出经过验证的 `Rptq` 查询图和布局树，并在拒绝-修复循环中使用引擎的解析器/验证器，使模型从不编写未经检查的原始 SQL，也从不自行计算聚合。
* **AI 辅助本地化**——跨语言区域翻译静态报表标签和元数据。

## 5. 驱动、导出格式与无头引擎

* **新的数据库驱动**——为云数据仓库和 API（Snowflake、BigQuery、DuckDB、REST/JSON、Salesforce SOQL）继承 `MADDatabase`。
* **Linux 无头 PDF 写入器**——完成 Linux 上非 UIKit 的 PDF 渲染路径（记录在 [`MAD_PDF_LINUX.md`](MAD_PDF_LINUX.md)；`html`、`html-flow`、`json`、`json-report`、`csv` 和 `text` 已在两个平台上发布）。
* **丰富的办公导出格式**——在 `<MADReportExporting>` 接缝上提供原生 Excel（`.xlsx`）、Word（`.docx`）和富文本导出器。
* **可视化查询构建器中的 `ORDER BY`**——在查询设计器 UI 中提供显式排序，超越由分组驱动的排序描述符。
* **编辑数据库连接信息**——允许在 UI 中将现有 `.mad` 文档重新指向新的主机/数据库（已通过 `mad` CLI 中的 `--host`/`--port`/`--database` 支持）。
* **可选的文档加密**——在请求时对静态存储的 `.mad` 归档进行加密。

## 6. 应用、Viewer 与 UI 打磨

* **独立的 MAD Viewer 应用目标**——完善解耦的 Viewer 目标（`Targets/MADViewer/`），使其成为 `.mad` 文档和快照的轻量读取器与刷新器。
* **打印与页码易用性**——MAD Viewer 中专用的打印操作，以及内置的页面 `N of M` 元素标记。
* **后台刷新与通知**——在后台运行长时间的数据库刷新，并在完成时发布本地通知。
* **自动报表缩略图**——在保存/刷新时渲染 `thumbnail@2x.png` 并将其存储到 `AdditionalContent/` 中，供文件浏览器使用。
* **设计器与查询 UI 打磨**——边框样式与边距/内边距保持一致；为较长的生成 SQL 文本提供水平滚动；查询可视化图布局与缓存改进；分页滑块悬停效果；About 弹出框着色；云活动指示器清理。
